# SportHub

SportHub es una tienda web de artículos deportivos. Permite explorar y filtrar el catálogo, consultar el detalle de cada producto, gestionar un carrito, registrarse o iniciar sesión y completar el flujo de compra.

## Acceso web

Puedes utilizar la aplicación desplegada en:

[Abrir SportHub](https://football-hub-murex.vercel.app/)

## Requisitos

- Node.js 20.19 o superior (requerido por Vite 8)
- npm o pnpm
- Una cuenta y un proyecto de Supabase para autenticación y base de datos

## Instalación

1. Clona el repositorio y entra en la carpeta del proyecto:

   ```bash
   git clone https://github.com/Gallegos13/FootballHub.git SportHub
   cd SportHub
   ```

2. Instala las dependencias del frontend:

   ```bash
   npm install
   ```

3. Crea un archivo `.env` en la raíz con las credenciales públicas de Supabase:

   ```env
   VITE_SUPABASE_URL=https://tu-proyecto.supabase.co
   VITE_SUPABASE_ANON_KEY=tu_clave_anonima
   ```

### Backend local y base de datos propia (opcional)

Los siguientes pasos solo son necesarios si quieres utilizar tu propia base de datos en lugar de la API publicada.

4. Instala las dependencias del backend:

   ```bash
   cd Backend
   npm install
   ```

5. Crea `Backend/.env` con la conexión de PostgreSQL:

   ```env
   DATABASE_URL=postgresql://usuario:contrasena@host:5432/base_de_datos
   PORT=3000
   ```

6. Crea la tabla que espera el frontend desde el editor SQL de Supabase o desde tu cliente de PostgreSQL:

   ```sql
   CREATE TABLE productos (
     id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
     nombre TEXT NOT NULL,
     descripcion TEXT NOT NULL DEFAULT '',
     precio NUMERIC(10, 2) NOT NULL CHECK (precio >= 0),
     imagen TEXT NOT NULL,
     categoria TEXT NOT NULL,
     deporte TEXT NOT NULL,
     marca TEXT NOT NULL,
     tallas TEXT,
     stock INTEGER NOT NULL DEFAULT 0 CHECK (stock >= 0)
   );
   ```

7. Agrega al menos un producto para que el catálogo pueda mostrar información:

   ```sql
   INSERT INTO productos
     (nombre, descripcion, precio, imagen, categoria, deporte, marca, tallas, stock)
   VALUES
     ('Jersey deportivo', 'Jersey oficial para aficionados.', 1299.00,
      'https://ejemplo.com/imagen.jpg', 'Ropa', 'Fútbol', 'SportHub',
      'CH,M,G,XG', 10);
   ```

La columna `imagen` debe contener una URL pública accesible desde el navegador. Las tallas se guardan en una cadena separada por comas, por ejemplo `CH,M,G,XG`, porque el frontend utiliza ese formato.

> No compartas los archivos `.env` ni incluyas credenciales reales en el repositorio.

## Uso

Inicia el frontend desde la raíz del proyecto:

```bash
npm run dev
```

Abre la dirección que Vite muestre en la terminal, normalmente `http://localhost:5173`.

Para iniciar la API local, abre otra terminal:

```bash
cd Backend
npm run dev
```

La API local quedará disponible en `http://localhost:3000`. Por defecto, el frontend utiliza la API existente en `https://footballhub-vpka.onrender.com`; no necesitas cambiarla si solo quieres ejecutar o probar SportHub. Si deseas usar tu propia base de datos, sustituye la URL base de las peticiones en `src/App.jsx`, `src/detalleproducto.jsx` y `src/pago.jsx` por `http://localhost:3000`.

## API REST

URL pública: `https://footballhub-vpka.onrender.com`

| Método | Endpoint | Descripción |
| --- | --- | --- |
| `GET` | `/productos` | Obtiene todos los productos ordenados por ID |
| `GET` | `/productos/:id` | Obtiene un producto por su ID |
| `POST` | `/actualizar-stock` | Descuenta del inventario las unidades compradas |

Ejemplo de producto devuelto por la API:

```json
{
  "id": 1,
  "nombre": "Jersey deportivo",
  "descripcion": "Jersey oficial para aficionados.",
  "precio": "1299.00",
  "imagen": "https://ejemplo.com/imagen.jpg",
  "categoria": "Ropa",
  "deporte": "Fútbol",
  "marca": "SportHub",
  "tallas": "CH,M,G,XG",
  "stock": 10
}
```

El endpoint de actualización de existencias recibe este formato:

```json
{
  "items": [
    { "id": 1, "cantidad": 2 }
  ]
}
```

## Autenticación con Supabase

La aplicación permite registro e inicio de sesión con correo y contraseña, además de acceso con Google. En un proyecto propio de Supabase debes:

1. Habilitar el proveedor **Email** en `Authentication > Providers`.
2. Para usar Google, habilitarlo y configurar sus credenciales OAuth.
3. Agregar `http://localhost:5173` y la URL desplegada a las URLs de redirección permitidas.
4. Colocar la URL y la clave anónima del proyecto en el archivo `.env` del frontend.

La variable `VITE_SUPABASE_ANON_KEY` se utiliza en el navegador y debe contener únicamente la clave pública anónima. Nunca coloques una clave `service_role` en variables cuyo nombre comience con `VITE_`.

## Despliegue

### Frontend en Vercel

- Directorio raíz: la raíz del proyecto
- Comando de compilación: `npm run build`
- Directorio de salida: `dist`
- Variables requeridas: `VITE_SUPABASE_URL` y `VITE_SUPABASE_ANON_KEY`

### Backend en Render

- Directorio raíz: `Backend`
- Comando de instalación: `npm install`
- Comando de inicio: `npm start`
- Variable requerida: `DATABASE_URL`

Render proporciona la variable `PORT` automáticamente. El servidor también utiliza el puerto `3000` como valor predeterminado durante el desarrollo local.

## Funcionalidades principales

- Catálogo con búsqueda y filtros por categoría, deporte y marca
- Vista detallada de productos
- Carrito persistente mediante `localStorage`
- Control de cantidades, tallas y disponibilidad
- Registro e inicio de sesión con Supabase
- Flujo de pago e historial de compras
- API para consultar productos y actualizar existencias

## Limitaciones actuales

- El carrito y el historial de compras se guardan en `localStorage`; no se sincronizan entre dispositivos y se pierden al borrar los datos del navegador.
- El frontend contiene directamente la URL de la API publicada. Para cambiar de entorno hay que modificarla en los archivos que realizan peticiones.
- La actualización de existencias forma parte de un proyecto demostrativo y no sustituye las validaciones y transacciones necesarias en un sistema de comercio electrónico en producción.
